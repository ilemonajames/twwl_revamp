# Application review and improvement plan

Reviewed: 22 October 2026

## Scope and assessment

This is a Laravel 10 / Livewire 3 application covering public counselling content, services and programs, client appointments, Square checkout, events, newsletters, and website administration. The feature coverage is broad, but authentication, authorization, payments, and booking integrity need attention before further feature expansion.

This review inspected source code, routes, models, migrations, layouts, dependency manifests, and the existing tests. It is not a production penetration test or a visual/browser audit. Deployment configuration, actual database constraints, third-party credentials, and production behavior were not verified. The initial review did not change application behavior; the subsequent implementation is recorded below.

## Implementation status — 22 October 2026

- **Implemented:** token-validated password reset on both canonical and legacy routes; active/verified role checks on service writes and all website-admin Livewire components; removal of the public paid-booking finalizer; active-account login checks; enforced email verification; public endpoint throttles and input bounds.
- **Implemented:** shared booking/rescheduling service with calendar locks and cross-midnight conflict checks; guest Appointment persistence; database-derived program pricing; nullable guest/service relations; immutable cart orders and payment attempts; typed Square calls with durable idempotency keys; verified amount/currency/location/reference before completion; signature-verified webhook replay protection; client payment history; safe cancellation and preservation of financial/booking history.
- **Implemented:** missing resource and media detail routes/views; duplicate route-name fixes; DELETE-only program deletion; bounded chat upstream calls and safe errors; individual queued newsletter delivery records; shared HTML/body/asset fixes; About heading/style corrections; social image metadata; profile schema/form repairs; isolated test configuration; environment/setup/deployment documentation and application CI. The existing Semgrep workflow's invalid cron entry was removed.
- **Verified locally:** 56 tests and 408 assertions passed on forced in-memory SQLite; frontend production build passed after compatible npm updates; temporary route caching passed; patch whitespace checks passed. Production npm dependency audit reports zero vulnerabilities.
- **Unresolved dependency upgrade:** Composer reports 51 advisories affecting 15 locked PHP packages. Its dry-run resolver refuses the Laravel 10 constraint because available releases in that constraint are affected. No security advisory ignore rules were added and no PHP packages were changed. Full npm audit still reports 10 findings in development dependencies requiring toolchain changes; the production dependency audit is clean. The new dependency-audit CI job deliberately exposes these outstanding findings.
- **Required before production release:** resolve the framework/runtime and development-toolchain upgrade, test migrations on a restored MySQL database, reconcile any legacy orphan/empty-string relations, verify parallel MySQL reservations, configure and exercise Square sandbox webhooks and queue workers, and perform browser/mobile/keyboard checks and backup restoration. No existing application database migrations, live charges, or deployment were performed.

See [deployment instructions](docs/DEPLOYMENT.md) for the exact operational requirements and limitations. Broader content sanitization/upload review, removal of unused legacy views, measured performance work, and full visual/accessibility review remain follow-up work rather than completed claims.

## Findings and ordered backlog

### Current design direction — 23 October 2026

Per the user's correction, the original hero slider, homepage section structure, shared navigation/footer, and existing scheme-02 palette are retained. The earlier standalone landing-page overhaul is superseded, and its unused templates and stylesheet have been removed.

Refinements now use `public/assets/css/site-refinements.css`, loaded by the public, guest, client, and website-administration layouts. They improve button/form consistency, card/table spacing, mobile layout, keyboard focus, navigation semantics, and image handling while retaining existing typography and the gold `#cda237`, green `#40633B`, and sage `#A8B6A4` colors. The original slideshow includes a pause control and respects reduced-motion preferences. The mobile menu supports Escape, focus containment, and an announced open/closed state.

Verification: the full isolated suite passed (56 tests / 408 assertions); subsequent public-page checks passed (6 tests / 21 assertions); frontend build, slider JavaScript syntax, and patch whitespace checks passed. Browser checks covered the original homepage at desktop/mobile sizes, mobile-menu opening and Escape dismissal, mobile About, and desktop Contact. These checked pages had no horizontal overflow. Shared styles reach account/admin layouts, but every authenticated screen has not been individually visually audited.

### Landing-page design update — 23 October 2026

The user reports that the application migrations have been applied. This update did not rerun them or alter application data.

The landing page now has a static editorial hero, cream/gold/green styling, clear appointment links, service cards, a founder introduction, database-driven programs/team/products, native accessible FAQ disclosures, a newsletter footer, and a separate responsive navigation. Browser checks at desktop width and a 390px mobile viewport confirmed no horizontal overflow, working mobile navigation with Escape dismissal, expandable FAQs, and no broken loaded images. This completes the landing-page design update, not the entire application backlog. Dependency/runtime upgrades, provider sandbox testing, MySQL concurrency validation, broader content/upload review, and backup/restore validation remain as described above.

## Delivery sequence

1. **Immediate containment — P0:** fix SEC-01, SEC-02, and PAY-01 first. If deployed, temporarily disable the vulnerable actions until fixes are verified. Establish isolated regression tests alongside these changes.
2. **Reliable core journeys — P1:** repair routing and guest booking, then implement one payment/order workflow and atomic appointment reservation. Inspect and migrate database relationships safely. Prove guest booking, client booking, cart checkout, and administrator edits in a sandbox environment.
3. **Operational baseline — P1/P2:** add CI, upstream request limits, queued notifications, observable failures, and deployment/restore instructions. Verify dependency status before selecting upgrade targets.
4. **Experience and maintainability — P2:** consolidate layouts/assets and obsolete code, then improve responsive behavior, accessibility, metadata, and content consistency. Measure browser performance before setting optimization targets.

The sequence is ordered by dependency and impact, not a committed calendar estimate. Size each work item after route discovery, database inspection, and a reproducible test environment are available.

## Release gates

- Password reset requires proof of token ownership; unauthorized users cannot mutate managed content or mark appointments paid.
- Payment amounts come from server records; retries and webhook replay cannot duplicate charges or fulfillment.
- Overlapping bookings are rejected atomically; database relationships match model key types.
- Route discovery, a fresh test migration, application tests, and the frontend build pass in CI.
- Main public/client/admin journeys pass browser checks; deployment rollback and backup restoration are documented and tested.

## Validation limits

The initial review found no AGENTS.md instructions. The working tree was clean at review start. PHP, Composer, Node, vendor dependencies, and node_modules are present. Initial route discovery failed because ResourceController did not exist, and database-resetting tests were initially withheld until isolation was implemented. The subsequent implementation repaired route discovery and ran the suite against forced in-memory SQLite. The repository's existing Semgrep workflow was also found during implementation. No live payment requests or existing application database migrations were performed. MySQL-specific schema changes, real provider integration, browser behavior, and restoration remain deployment validation requirements.
